# Mirage defender notification

## Live notification smoke test

With the main backend and webhook tunnel running, open `http://localhost:8787/mirage.html` and click **Run (watcher ON)** once. This scripted run emits a Mirage verdict into the main server's event bus and, in live voice mode, sends a real alert and places a real call. The analyst should receive the alert, answer the call, receive a six-digit code after `send_code`, read it back, and hear the briefing only after `verify_code` succeeds. Check `/api/audit` for `call.mirage_outbound` and `call.verified`, and `/api/calls` for the latest session's `verified` state. The outbound-call event alone does not prove that verification or briefing succeeded.

Do not run the dashboard's **watcher OFF** contrast while `VOICE_MODE=live`: the current mock driver still emits the raw suspicious `watcher.verdict` even though the Mirage engine routes that call as `pass`, so the notification bridge can send a real text and call during a watcher-off run. The event contract needs to report the effective verdict before that contrast can safely use live notifications.

The main server subscribes to `tool.call` and `watcher.verdict` on its shared event bus. The first `mirage` or `block` verdict in an attacker session sends a short Photon text, then calls the registered analyst through ElevenLabs. Repeated verdicts in that session are suppressed. If the call fails after the text succeeds, the next verdict retries only the call. Outgoing messages never include attacker text or watcher reasons.

`VOICE_MODE=mock` keeps the offline demo: `npx tsx server/voice/demo-notification.ts`. With `VOICE_MODE=live`, the server validates Photon, ElevenLabs, the webhook secret, and a **real registered analyst number** at startup. It will fail instead of silently logging mock notifications. Set `PHOTON_MODE=live`, `PHOTON_CHANNEL=imessage`, `PHOTON_PROJECT_ID`, `PHOTON_API_KEY`, `ELEVENLABS_AGENT_ID`, `ELEVENLABS_API_KEY`, `ELEVENLABS_PHONE_NUMBER_ID`, `VOICE_WEBHOOK_SECRET`, and `ANALYST_PHONE`. The analyst number must have role `analyst` in `data/users.json` and must not be a `+1555` demo number. The analyst must have messaged the Photon shared line first if Photon requires inbound iMessage initiation.

The ElevenLabs outbound call sends a Mirage-specific first message and system prompt override. In the agent Security tab, allow **First message** and **System prompt** overrides. Attach three **Webhook** tools to the published agent, all with method `POST`, `Content-Type: application/json`, and a Secret header named `x-batman-secret` whose value matches `VOICE_WEBHOOK_SECRET`:

| Tool name | URL | Body parameters |
| --- | --- | --- |
| `send_code` | `https://<backend>/voice/tools/send-code` | `conversation_id` = `{{system__conversation_id}}`; `caller_id` = `{{system__caller_id}}` |
| `verify_code` | `https://<backend>/voice/tools/verify-code` | Same two system variables; `code` is a six-digit string supplied by the caller |
| `mirage_briefing` | `https://<backend>/voice/tools/mirage-briefing` | Same two system variables |

Configure `conversation_id` and `caller_id` as dynamic-variable values in the tool body, not values generated by the agent. The server uses the conversation ID to pin an outbound call to the dialed analyst and its Mirage trigger. It sends the code to that registered number and releases the briefing only after server-side verification. `mirage_briefing` is read-only; it does not approve any fix.

The notification event bus, outbound-call map, verification codes, and tool routes must run in **the same backend process**. A standalone voice-only deployment cannot receive Mirage events produced by a separate local server. For an end-to-end live demo, expose the main server (`server/index.ts`) at stable HTTPS and point all three tool URLs there. If a call spans a process restart, its in-memory outbound map and verification code are lost; restart the test call.

For a short Cloudflare Quick Tunnel test on Windows, run the main server with `npm run dev`, run `npx tsx server/voice/tunnel-proxy.ts` in a second terminal, then run `.\.tools\cloudflared.exe tunnel --url http://127.0.0.1:3003` in a third. The proxy forwards only the authenticated voice webhook routes to the main server and exposes `/health` for a connectivity check. Use the printed `https://...trycloudflare.com` address for `/voice/init` and each tool URL. Keep the computer and all three processes running; Quick Tunnel URLs are temporary and change when the tunnel restarts. This test setup is separate from `VOICE_MODE=live`, which still requires the ElevenLabs API key and phone-number ID.
